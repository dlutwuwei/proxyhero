# ProxyHero 使用指南

ProxyHero 是一款本地 MITM 抓包桌面工具，面向接口联调场景。本文介绍日常使用：抓包、改写、证书与真机调试。

实现原理见 [架构与抓包原理](architecture-and-capture_zh.md)。

## 1. 界面概览

| 页面 | 用途 |
|------|------|
| **流量** | 会话列表、筛选、Inspector 详情 |
| **映射规则** | Map Remote / Map Local 改写 |
| **SSL** | 控制哪些 HTTPS 域名做 MITM 解密 |
| **证书** | 生成、安装、诊断根 CA |
| **设置** | 端口、语言、系统代理、局域网联调说明 |

顶栏显示代理状态与端口。**启动代理** / **停止代理** 在「流量」和「设置」中均可操作。

## 2. 启动与停止代理

点击 **启动代理** 会：

1. 启动本地 MITM 代理服务
2. 开启系统代理（指向 `127.0.0.1:<端口>`）

在 **macOS** 上，启用代理时会清除系统「代理绕过」中的内网 IP 段，使 `http://192.168.x.x` 等地址也走代理。停止代理或退出应用后会自动恢复原有绕过列表。

点击 **停止代理** 关闭服务并恢复系统代理设置。

> 在「设置」中修改端口后，需重启代理才生效。

## 3. 流量

### 会话列表

- 虚拟滚动，支持大量会话
- 列：客户端、方法、状态、时间
- **↑ / ↓** 方向键切换选中会话（焦点不在输入框时）

### 工具栏

- **监听地址**：有局域网 IP 时显示（如 `192.168.1.5:8888`）
- **清空**：清除全部已抓会话
- **搜索**：按 Host、URL、客户端、UA 过滤
- **协议**：全部 / HTTP / HTTPS
- **状态**：全部 / 进行中 / 2xx / 4xx / 5xx

### 侧栏

- **域名**：按 Host 分组筛选
- **客户端**：按客户端标识分组（来自 User-Agent 等）
- **收藏**：点击 ☆ 或右键收藏域名/客户端，在「收藏」页快速访问

### Inspector

选中会话后，底部 Inspector 左侧为请求、右侧为响应。

| 标签 | 内容 |
|------|------|
| 头部 | 请求/响应头 |
| 查询 | URL 查询参数 |
| 正文 | 解码后的正文 |
| Cookies | Cookie 键值 |
| 原始 | 原始 HTTP 报文 |
| 摘要 / 树形 | JSON 摘要或树形视图（响应） |

其他操作：

- **复制 cURL**：将请求重建为 cURL 命令并复制
- **规则**：显示命中的 Map 规则（如有）

> 响应正文超过 1 MB 时界面会截断显示，状态栏会标注完整大小。

## 4. 映射规则

在不改客户端的前提下改写流量。

### Map Remote

将匹配请求转发到其他上游（例如测试环境 API → 本地开发服务）。

| 字段 | 说明 |
|------|------|
| 名称 | 规则备注 |
| 协议 | 匹配协议（`http` / `https`） |
| 匹配 Host | 要匹配的域名 |
| 匹配 Path | 路径前缀；留空表示全部路径 |
| 目标协议 / Host / Port | 转发目标 |
| 保留 path / query | 是否保留原路径与查询串 |

**内置预设**（一键应用）：

| 预设 | 效果 |
|------|------|
| 本地 API (8080) | `https://api.example.com` → `http://127.0.0.1:8080` |
| 本地开发服务 (3000) | `https://localhost` → `http://127.0.0.1:3000` |

预设会合并进现有规则，不会清空全部规则。

### Map Local

用本地文件作为 HTTP 响应（Mock / 静态数据）。

| 字段 | 说明 |
|------|------|
| 匹配 Host / Path | 要拦截的请求 |
| 本地文件 | 响应文件的绝对路径 |
| HTTP 状态码 | 响应状态（默认 200） |
| 响应头 | 可选（如 `Content-Type`） |

### 规则优先级

- 每条规则可单独启用/禁用
- **order** 数值越小优先级越高
- Map Local 优先于 Map Remote 匹配

## 5. SSL

控制 HTTPS 是否解密（MITM）。解密须已信任 **ProxyHero CA**。

| 模式 | 行为 |
|------|------|
| 默认 | 除 **Exclude** 列表外全部 MITM |
| 仅 Include | 只解密 **Include** 列表中的域名 |
| 默认 + Exclude | 同默认；Exclude 中的域名仅隧道转发，不解密 |

**Exclude** 中的域名以加密隧道转发，Traffic 中看不到明文。

## 6. 证书

### 本机生成与安装

1. 打开 **证书**
2. 点击 **生成证书**，创建 **ProxyHero CA**
3. 点击 **安装到系统**（macOS 写入钥匙串）
4. 查看 **信任诊断**：代理 CA 指纹应与钥匙串 CA 指纹一致
5. 新安装或重新生成后，重启代理与浏览器

### 下载地址（手机 / 手动）

代理运行时可访问：

- 本机：`http://127.0.0.1:<端口>/proxyhero/ca.crt`
- 局域网设备：`http://<电脑IP>:<端口>/proxyhero/ca.crt`

「证书」页在代理启动后会显示二维码与分步说明。

### 重新生成

**重新生成** 会创建新的根 CA。须删除钥匙串中的旧 CA、安装新证书并重启代理，否则浏览器会报证书错误。

## 7. 设置

| 选项 | 说明 |
|------|------|
| 语言 | 中文 / English |
| 代理端口 | 默认 `8888`；保存后需重启代理 |
| 启动 / 停止代理 | 同流量页工具栏 |
| 外部设备联调 | 局域网 IP 与手动配置代理说明 |

### 不使用系统代理的浏览器

```text
--proxy-server=127.0.0.1:8888 --proxy-bypass-list=""
```

## 8. 典型流程

### 本机联调

1. **证书** → 生成 → 安装 → 确认指纹一致
2. **流量** 或 **设置** → **启动代理**
3. 可选：**映射规则** → 应用预设或添加自定义规则
4. 在浏览器或 App 中访问目标；在 **流量** 中查看明文
5. 结束后 **停止代理**（退出应用也会自动恢复系统代理）

### 手机抓包

1. 手机与电脑连接 **同一 Wi-Fi**
2. **设置** → 查看电脑局域网 IP（如 `192.168.x.x`）
3. 手机 Wi-Fi → HTTP 代理 → 服务器填电脑 IP，端口 `8888`
4. 手机浏览器打开 `http://<电脑IP>:8888/proxyhero/ca.crt` 下载并安装证书
5. **iOS**：设置 → 通用 → VPN 与设备管理 → 安装描述文件 → 通用 → 关于本机 → 证书信任设置 → 开启 **ProxyHero CA**
6. **Android**：设置 → 安全 → 从存储设备安装 → 选择「VPN 和应用」信任
7. 在手机上使用目标 App，电脑 **流量** 页即可看到请求

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| `NET::ERR_CERT_AUTHORITY_INVALID` | 删除钥匙串旧根 CA（含 **LK Debug Proxy CA**）→ 在证书页重新生成并安装 → 重启代理与浏览器 |
| HTTPS 无法解密 | 确认 CA 已信任；检查 SSL Exclude；客户端可能做了证书固定 |
| 抓不到包 | 确认已启动代理；手机检查 Wi-Fi 代理；仅抓经代理转发的流量 |
| 访问 IP 地址不走代理（macOS） | 使用 **启动代理**（会取消内网绕过）；或浏览器加 `--proxy-bypass-list=""` |
| 指纹不一致 | 重新安装 CA；点击 **刷新诊断** |
| Map 规则未生效 | 规则是否启用？Host/Path 是否匹配？检查规则配置中的允许映射 Host |

## 10. 数据与配置文件

应用数据目录（由 Tauri 管理，路径因系统而异）：

| 文件 | 内容 |
|------|------|
| `config.json` | 端口、系统代理状态 |
| `rules.json` | Map 与 SSL 规则 |
| `certs/proxyhero-ca.crt` | 根 CA 证书与私钥 |

## 11. 使用限制

- 解密 HTTPS 须信任 **ProxyHero CA**；做了 **Certificate Pinning** 的客户端无法 MITM
- 仅抓取经代理转发的流量（devServer 等服务端转发段不经过浏览器代理）
- HTTP/2 多路复用下同连接按 FIFO 关联请求/响应，极高并发下可能偶发错配
- 仅供本地联调，不替代生产网关或后端鉴权
